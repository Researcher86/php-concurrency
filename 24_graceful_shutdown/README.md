# 24. Graceful Shutdown

Мягкое завершение: по SIGTERM система дорабатывает и чистится, а не падает.

## Задача

По сигналу остановки не выходить мгновенно (потеря задач, зомби, забитая
очередь), а пройти полный цикл: перестать принимать новое → доесть очередь →
завершить активные задачи → закрыть IPC → дождаться детей → выйти.

## Как работает

Последовательность по SIGTERM у мастера:
1. **Stop accepting** — флаг `$isShutdown = true`, приём новых задач прекращён.
2. **Drain queue** — ожидание, пока очередь не опустеет (`msg_qnum == 0`).
3. **Finish active** — воркеры дорабатывают текущее.
4. **Close IPC** — воркерам шлётся STOP, мастер собирает их `waitpid`.
5. **Cleanup** — `msg_remove_queue`, тишина.

Демо: таймер-процесс шлёт мастеру SIGTERM посреди потока задач; видно, что
все задачи обработаны, очередь пуста, зомби нет.

## IPC

System V очередь; сигналы (`pcntl_signal`, `pcntl_async_signals`),
`posix_getppid()` в таймере; `pcntl_waitpid`.

## Паттерн

**Graceful Shutdown / Drain** — управляемое завершение без потерь.

## Запуск

```bash
docker compose exec -T php php /app/24_graceful_shutdown/main.php
```

## Что попробовать изменить

- Убрать drain (мгновенный exit) — часть задач потеряется.
- Увеличить задержку таймера — SIGTERM придёт после отправки всех задач.
- Добавить N задач больше — увидеть, как drain ждёт именно воркеров.

## Real world

Kubernetes (SIGTERM + grace period), PHP-FPM (SIGQUIT), nginx, Kafka consumer
(rebalance-остановка).
