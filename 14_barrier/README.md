# 14. Barrier

Фаза 2 ни у кого не начнётся, пока ВСЕ процессы не завершат фазу 1.

## Задача

Синхронизация фаз: несколько процессов работают независимо, но следующая
фаза начинается у всех только после того, как все закончили предыдущую.

## Как работает

- Каждый воркер делает фазу 1 (случайное время работы).
- По завершении увеличивает общий счётчик в shared memory под семафором.
- Воркеры ждут (spin, `usleep(1000)` + проверка счётчика), пока счётчик
  не достигнет `WORKER_COUNT`.
- Последний пришедший "отпускает" барьер — все одновременно начинают фазу 2.

## IPC

System V shared memory (счётчик) + semaphore (атомарный инкремент).

## Паттерн

**Barrier** — точка синхронизации всех участников (SPMD-стиль).

## Запуск

```bash
docker compose exec -T php php /app/14_barrier/main.php
```

## Что попробовать изменить

- Сделать фазу 2 тоже разной длительности — увидеть, что она всё равно
  стартует у всех вместе.
- Добавить второй барьер (нужен сброс счётчика).
- Убрать spin-ожидание и посмотреть на гонку в выводе.

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — синхронизация через shm + spin-ожидание.
**Failure modes**: участник умирает до барьера → все остальные ждут вечно
(нужен таймаут); spin-ожидание жжёт CPU; гонка, если счётчик сбрасывается
неверно.
**Guarantees**: новая фаза стартует у всех участников одновременно; барьер
собирает всех (SPMD); вторая фаза не начнётся, пока не пришли все.

## Real world

OpenMP `#pragma omp barrier`, CUDA `__syncthreads`, MPI_Barrier, Hadoop phases.
