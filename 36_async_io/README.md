# 36. Async I/O

Свой маленький асинхронный runtime: `awaitRead()` / `awaitMs()` прячут event
loop за фибрами — пользовательский код выглядит как обычные блокирующие
вызовы, но ничего не блокирует.

## Задача

Реализовать userland-API `await($stream)` поверх `Fiber::suspend()` +
`stream_select()` и показать, что один процесс с несколькими фибрами
обрабатывает запросы многих клиентов с перекрывающимся I/O.

## Как работает

- **Клиенты** — дочерние процессы, каждый шлёт несколько запросов по своему
  unix socket pair и закрывает канал (EOF = клиент закончил).
- **Фибра-обработчик** берёт поток, читает запросы через `awaitRead()` и
  "дорого" обрабатывает через `awaitMs()` (симуляция работы). При EOF берёт
  следующий поток из общей очереди — простой work-stealing.
- **`awaitRead()`** = зарегистрировать ожидание (`['read', $stream]`) через
  `Fiber::suspend()`; event loop вернёт `'ready' | 'eof' | 'timeout'`.
- **`awaitMs()`** = ожидание по таймеру через timeout `stream_select()`.
- **`runEventLoop()`** крутится, пока есть зарегистрированные ожидания:
  собирает read-набор и ближайший таймер, спит в `select()`, будит готовые
  фибры через `resume()`.

Отличие от урока 35: там loop был явным в main-цикле, здесь он спрятан за
`await*()` — получился настоящий runtime, где пользовательский код не видит
механику переключения.

## IPC

Unix socket pair (`stream_socket_pair`) — источники событий; клиенты —
форкнутые процессы, как в 11_pipeline.

## Паттерн

**Async/Await runtime (fiber + reactor)** — фибры прячут event loop за
"блокирующим" синтаксисом. Основа Amp v3 / Swoole.

## Запуск

```bash
docker compose exec -T php php /app/36_async_io/main.php
```

## Что попробовать изменить

- Уменьшить `SERVER_FIBERS` до 1 — увидеть сериализацию (I/O уже не
  перекрывается в рамках одной фибры).
- Увеличить `awaitMs` до секунды — наглядно увидеть, что loop продолжает
  обслуживать другие фибры, пока одна "спит".
- Заменить `awaitRead` на блокирующий `fgets()` — сервер встанет (анти-паттерн
  из урока 34).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐⭐⭐ — настоящий async runtime: регистрация ожиданий,
event loop, переключение фибер.
**Failure modes**: блокирующий вызов в фибре останавливает ВЕСЬ сервер
(кооперативность!); `'timeout'` без обработчика — фибра зависнет (тут время
ожидания фиксировано 1s); если клиент не закрывает канал — EOF не придёт, и
фибра будет ждать таймаут.
**Guarantees**: I/O-ожидания перекрываются внутри одного процесса; порядок
обработки зависит от готовности сокетов, а не от порядка клиентов; общее
время ≈ max(сумма работы одной фибры), а не сумма всей работы — перекрытие.

## Real world

Amp v3 (фиберы + Revolt loop), Swoole (coroutine + epoll), OpenSwoole;
ReactPHP — тот же loop, но с callbacks вместо фибер.
