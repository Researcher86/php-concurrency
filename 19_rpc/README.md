# 19. RPC

Удалённый вызов процедуры: клиент вызывает "функцию", исполняемую в другом
процессе.

## Задача

Выглядит как локальный вызов, работает удалённо: клиент передаёт аргументы,
серверный процесс выполняет и возвращает результат.

## Как работает

- Запрос и ответ идут через очереди.
- Каждый вызов получает **correlation id** — по нему ответ сопоставляется
  с конкретным запросом (клиентов много, ответы перемешиваются).
- Клиент блокируется, пока не получит ответ со своим id.

## IPC

System V очереди: request-очередь (клиент→сервер) и response-очередь
(сервер→клиент); correlation id как часть payload.

## Паттерн

**RPC / Request-Reply** с correlation id.

## Запуск

```bash
docker compose exec -T php php /app/19_rpc/main.php
```

## Что попробовать изменить

- Добавить второй серверный процесс — ответы будут приходить из разных мест.
- Добавить таймаут ожидания ответа (см. 17).
- Сделать брокер-посредник между клиентами и серверами.

## Real world

gRPC, JSON-RPC, RabbitMQ RPC pattern, HTTP request/response.
