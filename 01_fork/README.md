# 01. Fork

Основа всего курса: как из одного PHP-процесса получить несколько копий
процессов и разделить между ними код.

## Задача

Показать, что после `pcntl_fork()` в памяти находятся ДВА одинаковых процесса
(родитель и ребёнок), и что код после fork выполняется в обоих. Разделение
родитель/ребёнок — по возвращаемому значению `$pid`.

## Как работает

- Цикл дважды вызывает `pcntl_fork()` → получается 2 дочерних процесса.
- В ребёнке (`$pid === 0`) печатается номер и идёт свой цикл из 10 итераций.
- В родителе — свой цикл из 10 итераций.
- После завершения дети становятся зомби (процесс умер, но запись в таблице
  процессов осталась), пока родитель не вызовет `pcntl_wait()`. Финальный
  `while (pcntl_wait($status) !== -1)` собирает всех детей.
- В комментариях файла объясняется, зачем нужен `init: true` (tini) как PID 1:
  он репнит зомби-сирот и пробрасывает сигналы.

## IPC

IPC ещё нет — это разминка. Общение родителя и ребёнка пока только через
файловые дескрипторы, которые копируются при fork.

## Паттерн

Базовый механизм **Process Forking**. На нём построены все остальные уроки:
worker pool, fan-out, master-worker и т.д.

## Запуск

```bash
docker compose exec -T php php /app/01_fork/main.php
```

Идёт ~20 секунд (10 итераций × 2с в ребёнке).

## Что попробовать изменить

- Уменьшить `usleep` (2000000 → 100000), чтобы урок шёл быстрее.
- Добавить третий `pcntl_fork()`.
- Убрать финальный `pcntl_wait` и посмотреть в `ps -eo pid,ppid,stat` на зомби
  (статус `Z`).

## Real world

Каждый PHP-FPM-воркер, каждый `proc_open`, каждый запуск параллельной задачи
в Go/Python под капотом делает fork.
