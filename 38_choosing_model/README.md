# 38. Choosing the Model

Финальный сравнительный урок: процессы (pcntl) vs фибры (PHP 8.1+) — когда
какую модель выбирать. С замером на реальных задачах.

## Задача

Осознать границы обеих моделей конкурентности в PHP и уметь выбрать
инструмент под задачу: I/O-bound → фибры, CPU-bound → процессы.

## Как работает

- **Сравнительная таблица**: единица выполнения, адресное пространство,
  планирование, parallelism, memory, IPC, shared state, failure isolation.
- **Замер 1 — стоимость fork**: измеряем `fork()+waitpid()`. В этом контейнере
  ~100ms на вызов — процессы на КОРОТКИХ задачах дороги.
- **Замер 2 — I/O-bound** (100 задач × 20ms ожидания): последовательно,
  процессами батчами по 10, фибрами с event loop. Фибры выигрывают на порядки.
- **Замер 3 — CPU-bound** (12 задач × 800ms вычислений): процессы реально
  параллелятся на ядрах (≈4× быстрее), фибры дают ноль parallelism.

## Ключевые выводы

- **I/O-bound + много задач** (HTTP, DB, сокеты, таймеры) → **фибры**: тысячи
  задач в одном процессе, почти без памяти, без IPC.
- **CPU-bound** (изображения, компрессия, расчёты) → **процессы**: только они
  используют несколько ядер.
- **Изоляция падений** → **процессы**: упавший ребёнок не убивает родителя,
  упавшая фибра кладёт весь процесс.
- **Фибры не заменяют процессы**: они решают другую задачу (см. таблицу).

## IPC

Не используется (замеры изолированные); в процессных замерах — только
`fork()/waitpid()`.

## Паттерн

**Model Selection / Architecture Decision** — завершает курс сравнительным
анализом двух runtime-моделей (урок 32 — процессной, урок 37 — фиберной).

## Что попробовать изменить

- Уменьшить `CPU_MS` до 50 — увидеть, как fork-оверхед маскирует параллелизм
  (и сделать вывод: для коротких задач процессы невыгодны).
- Увеличить `IO_MS` — сдвинуть точку безубыточности процессов.
- Запустить на машине с другим числом ядер (`nproc`) и сравнить CPU-замер.

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — сравнительный урок; сложность не в коде, а в осознании
границ моделей.
**Failure modes**: цифры зависят от окружения (число ядер, скорость fork);
процессные замеры дорогие по времени (много форков); CPU-bound часть
чувствительна к конкурентной нагрузке на хосте.
**Guarantees**: повторяемость трендов (I/O → фибры, CPU → процессы), даже если
абсолютные числа различаются между машинами; fork-оверхед измеряется явно.

## Real world

- nginx — процессы (master + workers) и неблокирующий I/O.
- PHP-FPM — процессы-воркеры, каждый обрабатывает запросы в цикле.
- RoadRunner — процессные воркеры поверх Go-рантайма (goroutine-планировщик).
- Swoole/Amp — фиберы + event loop внутри одного процесса.
- Выбор в проде — часто гибрид: пул процессов + фибры внутри каждого.
