Choosing the Model (процессы vs фибры)

                    PHP Concurrency
                          │
        ┌─────────────────┴─────────────────┐
        │                                   │
   Processes (pcntl)                   Fibers (PHP 8.1+)
        │                                   │
   parallelism                         concurrency
        │                                   │
   OS-планирование                  userland-планирование
        │                                   │
   CPU-bound / изоляция              I/O-bound / event loop
        │                                   │
   IPC (очереди, сокеты)             общая память (без IPC)
        │                                   │
   упал ребёнок — жив родитель       упала фибра — упал процесс
        │                                   │
        └──────────────┬────────────────────┘
                       │
                       ▼
                Choosing the Model
   I/O + много задач      → фибры (event loop + await)
   CPU / расчёты          → процессы (несколько ядер)
   изоляция падений       → процессы
   тысячи соединений      → фибры (память на порядки меньше)

   Измерения (PHP 8.5, контейнер):
   I/O-bound 100×20ms : seq 2.3s | процессы 10.2s | фибры 0.02s
   CPU-bound 12×800ms : seq 9.6s | процессы 2.2s | фибры 9.6s

   Ключевой инсайт: fork стоит ~100ms — процессы дороги на коротких
   задачах, но незаменимы для параллельных CPU-расчётов.

─────────────────────────────────────────
Сложность: ⭐⭐⭐ — сравнительный урок, сложность в осознании границ обеих моделей
Syscalls:  fork(), waitpid(), select(), usleep() (замеры)
Real world: nginx (процессы) + OpenSSL non-blocking; PHP-FPM (процессы) + Amp (фибры);
           RoadRunner (процессы-воркеры) поверх Go-рантайма (goroutines)
