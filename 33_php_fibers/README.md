# 33. PHP Fibers

Механизм кооперативной приостановки выполнения PHP-кода внутри одного
процесса и одного потока (PHP 8.1+).

## Задача

Понять, что такое Fiber, чем он **не** является (не поток, не процесс, не
параллелизм), и как работает переключение `start/suspend/resume`.

## Как работает

- `new Fiber($callable)` — фибра ещё не запущена.
- `$fiber->start()` — начинает выполнение и останавливается на первом
  `Fiber::suspend()`; возвращает значение, переданное в `suspend()`.
- `$fiber->resume($value)` — возобновляет; `$value` становится результатом
  выражения `Fiber::suspend()` внутри фибры.
- `$fiber->getReturn()` — возвращаемое значение замыкания после завершения.
- `Fiber::getCurrent()` — текущая фибра (или null вне фибры).
- Состояния: `isStarted() / isSuspended() / isRunning() / isTerminated()`.

В демо показаны: базовый цикл, состояния, CPU-нагрузка (показывает отсутствие
параллелизма), кооперативное переключение между двумя фибрами и ошибка
`Fiber::suspend()` вне фибры.

## Терминология (важно)

- **Fiber ≠ Thread** — у фибры нет отдельного потока ОС; планирование
  происходит в userland, в одном потоке.
- **Fiber ≠ Process** — нет `fork()`, нет отдельного адресного пространства;
  фибра разделяет память и переменные с процессом напрямую, без IPC.
- **Fiber ≠ Parallelism** — одновременно выполняется только одна фибра.
  Parallelism дают процессы (или потоки, но не в stock CLI PHP).
- **Fiber = Concurrency** — возможность *кооперативно* переключаться между
  задачами. Аналог goroutine в Go, но без прерывания системных вызовов.

## IPC

Не требуется — фибры живут в том же процессе и адресном пространстве, что и
вызывающий код.

## Паттерн

**Coroutine / Fiber (cooperative multitasking)** — база для async-рантаймов.

## Запуск

```bash
docker compose exec -T php php /app/33_php_fibers/main.php
```

## Что попробовать изменить

- Добавить третий `suspend()` в фибре и проследить, сколько раз нужно `resume`.
- Убрать `suspend()` — фибра выполнится целиком за один `start()`.
- Вызвать `resume()` повторно на завершённой фибре (получите `Error`).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — сам механизм прост, сложность начинается со
связывания фибер с event loop (уроки 35–37).
**Failure modes**: `Fiber::suspend()` вне фибры → `Error`; повторный
`resume()`/`start()` завершённой фибры → `Error`; брошенное внутри фибры
исключение всплывает в том месте, где фибру возобновили; недовозобновлённая
фибра при сборке мусора печатает warning.
**Guarantees**: переключение только в точках `suspend()`/`resume()`;
одновременно исполняется одна фибра (нет параллелизма); память и переменные
общие без всякого IPC.

## Real world

Amp v3, Revolt — фиберы как способ писать асинхронный код «в синхронном
стиле». ReactPHP — пре-фиберный подход (callbacks/promises).
