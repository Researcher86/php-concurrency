# 35. Event Loop + Fibers

Связываем event loop (урок 18) с фибрами (уроки 33–34): фибры ждут события,
не опрашивая каналы, — их будит `stream_select()`.

## Задача

Показать, как выглядит настоящий асинхронный рантайм: фибра сама заявляет
через `suspend()`, чего она ждёт (готовность сокета или наступление таймера),
а event loop спит в `select()` и будит только те фибры, чьё событие готово.

## Как работает

- **Протокол регистрации**: фибра вызывает `Fiber::suspend(['read', $stream])`
  или `Fiber::suspend(['timer', $at])` — это возвращается наружу как "запрос".
- Event loop собирает запросы всех фибр в `$read`-набор и ближайший таймер.
- `stream_select()` спит до первого готового события (таймаут = до ближайшего
  таймера).
- Готовые фибры будим через `resume('ready')` / `resume('tick')`; фибра
  обрабатывает данные и снова `suspend()` со следующим запросом.
- Heartbeat — таймер-фибра: показывает, что loop будит её по времени, а не по
  данным.

Ключевое отличие от урока 18: там обработчики — функции в одном цикле. Здесь
у каждой задачи — свой стек (фибра), поэтому асинхронный код выглядит как
обычный последовательный.

## IPC

Unix socket pairs (`stream_socket_pair`) как источники событий (как в 18/11).
Таймеры реализованы через timeout `select()` — без отдельных процессов.

## Паттерн

**Reactor + Coroutines (event loop + fibers)** — архитектура Amp/Revolt.

docker compose exec -T php php /app/35_event_loop_fibers/main.php

## Что попробовать изменить

- Увеличить `HB_INTERVAL` — увидеть, как loop ждёт только таймер.
- Добавить третью фибру-читатель (ещё один источник).
- Заменить `fgets()` на чтение по фиксированному количеству байт — увидеть,
  как фибра переживает "частичную строку" (фрагментацию).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐⭐ — протокол "фибра сама заявляет интерес" непривычен
(сравните с генераторами и `yield`), отладка состояний сложнее.
**Failure modes**: блокирующий вызов в фибре останавливает ВЕСЬ loop (фибры
кооперативны, см. урок 34); фибра, которая не вернула новый запрос и не
завершилась, "зависает" навсегда; `stream_select` не любит пустой read-набор
(в коде — явная ветка с `usleep`).
**Guarantees**: loop не блокируется на источниках; будит только готовые фибры;
таймеры точны в пределах одного тика select; одна фибра в каждый момент
(никаких гонок на общих данных).

## Real world

Revolt (чистый event loop), Amp v3 (фиберы поверх Revolt), Swoole
(coroutine + epoll), Node.js libuv (но без фибер: callbacks/promises).
