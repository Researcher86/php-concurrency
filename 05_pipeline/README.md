# 05. Pipeline

Конвейер из стадий, как `|` в шелле: данные перетекают по цепочке процессов.

## Задача

Разбить обработку на последовательные стадии, каждая — отдельный процесс.
`source → stage1 → stage2` — как `cat file | grep foo | sort`.

## Как работает

- Каждая стадия — отдельный процесс (`pcntl_fork`).
- Между стадиями данные идут по `stream_socket_pair`: стадия читает из своего
  in-канала и пишет в out-канал следующей стадии.
- Первая стадия (source) генерирует данные, последняя — результат.
- Магическое число в коде вынесено в константу (например `DATA_COUNT`).

## IPC

Unix socket pair (`stream_socket_pair`) между соседними стадиями.

## Паттерн

**Pipeline / Filter-Stream** — линейная цепочка обработчиков. Лаг на каждой
стадии определяется самой медленной стадией (появляется узкое место).

## Запуск

```bash
docker compose exec -T php php /app/05_pipeline/main.php
```

## Что попробовать изменить

- Добавить третью стадию в конец цепочки.
- Сделать одну стадию сильно медленнее других — конвейер упрётся в неё.
- Соединить стадии через очередь System V вместо socket pair.

## Real world

Unix-конвейеры, stream processing (Logstash), HTTP-мидлвары.
