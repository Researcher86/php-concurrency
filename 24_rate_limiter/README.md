# 24. Rate Limiter

Несколько воркеров разделяют ОДИН общий лимит скорости (задач в секунду).

## Задача

Суммарная скорость всех воркеров не должна превышать лимит (например
5 задач/сек), даже если воркеров три. Лимит общий, а не на каждого.

## Как работает

- Общий счётчик задач и время следующего слота — в **shared memory**.
- **Семафор** делает операцию «взять номер задачи + забронировать слот»
  атомарной.
- Воркер берёт слот и **ждёт его ВНЕ блокировки** (`usleep`) — остальные
  воркеры не блокируются и занимают следующие слоты.
- Итог: задачи идут строго по `SLOT_S = 1 / RATE_PER_SEC`, но распределены
  по всем воркерам.

## IPC

System V semaphore (`sem_get`/`sem_acquire`/`sem_release`) + shared memory
(`shm_attach`/`shm_put_var`/`shm_get_var`); `microtime(true)` для слота.

## Паттерн

**Token Bucket (или глобальный pacing) на семафоре** — единый лимит на пул.

## Запуск

```bash
docker compose exec -T php php /app/24_rate_limiter/main.php
```

## Что попробовать изменить

- Поднять `RATE_PER_SEC` — интервал между слотами станет меньше.
- Убрать `sem_acquire`/`sem_release` — гонка испортит счётчик.
- Сделать burst: разрешить всплеск из K задач сразу (bucket capacity).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — семафор + shm-счётчик, модель проста.
**Failure modes**: без `sem_acquire`/`sem_release` — гонка портит счётчик;
слишком малый лимит — избыточные отказы; нет burst-ёмкости — резкие всплески
обрезаются.
**Guarantees**: глобальный темп на весь пул воркеров (не per-worker);
атомарность счётчика через семафор; лимит соблюдается даже при многих
воркерах.

## Real world

API gateways (rate limiting), nginx `limit_req`, Redis token bucket, AWS
Service Quotas.
