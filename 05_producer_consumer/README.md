# 05. Producer-Consumer

Производители и потребители через общую очередь (competing consumers).

## Задача

N производителей шлют сообщения в одну очередь, M потребителей их разбирают.
Разделить производство и потребление — чтобы они масштабировались независимо.

## Как работает

- N producer-процессов пишут сообщения в общую очередь.
- M consumer-процессов забирают сообщения (каждый получает очередное,
  конкурируя за очередь).
- Завершение — по **terminator**: после того как все продюсеры закончили,
  на каждого консюмера отправляется специальное сообщение-стоппер.

## IPC

System V очередь; `pcntl_waitpid` для сбора детей; цикл
`while (pcntl_wait(...))` — многострочный, чтобы не путать завершение
процессов с обработкой сообщений.

## Паттерн

**Producer-Consumer** — разделение на производство и потребление, очередь как
буфер. Вариант competing consumers (любой свободный потребитель берёт задачу).

## Запуск

```bash
docker compose exec -T php php /app/05_producer_consumer/main.php
```

## Что попробовать изменить

- Сделать продюсеров больше потребителей (и наоборот) и посмотреть, где
  возникает затык.
- Убрать terminator — консюмеры зависнут на пустой очереди.
- Добавить `usleep` продюсерам — очередь будет пустеть и наполняться.

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — простейшая развязка «производитель/потребитель».
**Failure modes**: потребители умерли, а продюсер продолжает → очередь растёт
до переполнения; потерян терминирующий сигнал → потребители висят на пустой
очереди.
**Guarantees**: очередь буферизует разницу скоростей; сообщения в SysV
очереди не теряются, пока очередь живёт и никто не пишет поверх лимита.
