# 37. Mini Async Runtime

Capstone второй половины курса: event loop + фибры + таймеры + async I/O +
scheduler — маленький асинхронный рантайм в одном процессе.

## Задача

Собрать из уроков 33–36 одну работающую модель асинхронного рантайма:
пул воркеров-фибер, фоновый демон и callback-таймер крутятся одновременно в
одном процессе — без `fork()`, без IPC, без блокировок.

## Как работает

- **Event loop** (`runLoop`) — сердце: собирает read/write-наборы из ожиданий
  всех фибер и ближайший таймер, спит в `stream_select()` и будит готовые
  фибры через `resume()`.
- **Async I/O** — `awaitRead($stream)` / `awaitWrite($stream)` регистрируют
  ожидание через `scheduleEvent()` + `Fiber::suspend()`, loop возвращает
  `'ready' | 'timeout'`.
- **Таймеры** — два вида: фиберные (`awaitMs()`) и callback-таймеры
  (`addTimer()` — heartbeat планировщика).
- **Scheduler** — `runInBackground($cb)` оборачивает задачу в фибру; честная
  userland-модель "фоновой задачи".
- **Worker pool** — N фибер-воркеров читают из своих сокетов, "обрабатывают"
  (awaitMs) и закрываются при EOF. Клиенты — тоже фибры (в том же процессе):
  пишут задачи в socket pair и закрывают канал. Демон-фибра тикает по таймеру.

## Контраст с уроком 32

Урок 32 (процессный рантайм): `fork()`, SysV-очереди, IPC, семафоры,
параллелизм (несколько ядер). Урок 37: один процесс, общая память, никакого
IPC, но только кооперативное переключение на I/O-ожиданиях. Это два разных
способа добиться "много задач": по-процессному и по-фиберному.

## IPC

Нет (фибры — тот же процесс). Сокеты нужны только для генерации событий:
клиенты-фибры (в том же процессе, без `fork()`) пишут в свои пары — это
источники I/O для event loop.

## Что попробовать изменить

- Добавить ещё одного демона и посмотреть перекрытие таймеров.
- Заменить `awaitMs` на `sleep()` в воркере — весь рантайм встанет
  (анти-паттерн из урока 34).
- Уменьшить `TASK_IO_MS` — увидеть, как раньше освобождаются воркеры.
- Добавить callback-таймер, который отменяет другую задачу (cancellation).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐⭐⭐ — capstone: все фибер-идеи курса в одном рантайме.
**Failure modes**: блокирующий вызов в любой фибре останавливает ВЕСЬ
рантайм; фибра, не возвращающая управление в suspend, "съедает" loop;
таймауты фиксированы — без обработки `'timeout'` фибра может зациклиться;
`select()` ограничен 1024 fd.
**Guarantees**: кооперативность — одна фибра исполняется в каждый момент,
остальные ждут события; I/O и таймеры перекрываются; общее время ≈ max(работы
одной цепочки), а не сумма всех задач; у фибер нет data races уровня потоков
(одновременно исполняется одна фибра), но логические гонки между точками
`suspend()` возможны.

## Real world

- **Revolt** — сам event loop (наш `runLoop`).
- **Amp v3** — фиберы поверх Revolt (наши `awaitRead`/`awaitMs`).
- **ReactPHP** — тот же loop, но с callbacks/promises вместо фибер
  (другой стиль, до фиберов).
- **Swoole** — coroutine + epoll в PHP-расширении.
- **Go runtime** — goroutine + scheduler, но с прерыванием блокирующего I/O
  (чего у PHP-фибер нет — это ключевое отличие).
