# 22. Mini PHP-FPM

Мастер держит пул воркеров, каждый умирает после `pm.max_requests` запросов и
перезапускается — как настоящий FPM.

## Задача

Воркеры постепенно накапливают утечки (память, дескрипторы). Решение FPM —
убивать воркера после N запросов и заменять свежим.

## Как работает

- Мастер форкает пул воркеров.
- Каждый воркер принимает запросы из общей очереди и обрабатывает до
  `pm.max_requests`.
- После `pm.max_requests` воркер завершается сам (имитация утечки) и
  перезапускается мастером (supervisor).
- Получается цикл: пул всегда полный, воркеры всегда "чистые".

## IPC

System V очередь запросов; `pcntl_waitpid` (WNOHANG) + respawn; неблокирующий
`MSG_IPC_NOWAIT` приём.

## Паттерн

**Worker Recycling** (pm.max_requests) + Supervisor.

## Запуск

```bash
docker compose exec -T php php /app/22_mini_php_fpm/main.php
```

## Что попробовать изменить

- Уменьшить `pm.max_requests` — рестарты станут чаще, это видно в логе.
- Добавить искусственную утечку (растущий массив) и увеличить лимит.
- Сделать плавный рестарт: не терять текущий запрос.

## Real world

PHP-FPM (`pm.max_requests`), uwsgi (`max-requests`), gunicorn
(`max_requests`).
