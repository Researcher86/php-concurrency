# 20. Work Stealing

Перегруженный воркер крадёт задачи из чужих очередей — нагрузка балансируется
сама.

## Задача

Мастер раскладывает первичные задачи неравномерно (перегружает W1). Хочется,
чтобы все воркеры закончили почти одновременно.

## Как работает

- Общая очередь задач + отдельная "домашняя" очередь у каждого воркера.
- Мастер раскладывает задачи по домашним очередям (W1 перегружен).
- Когда воркер опустошил свою очередь И общую — он **крадёт задачи из чужих
  домашних очередей**.
- Нагрузка балансируется динамически, без вмешательства мастера.
- Итог: 5 краж у перегруженного W1, все заканчивают вместе.

## IPC

System V очереди: одна общая + по одной на воркера. Техника ревью:
неблокирующий приём `MSG_IPC_NOWAIT` + SIGTERM-хендлер, объявленный до fork.

## Паттерн

**Work Stealing** — динамический баланс нагрузки (Go scheduler, Java
ForkJoinPool).

## Запуск

```bash
docker compose exec -T php php /app/20_work_stealing/main.php
```

## Что попробовать изменить

- Убрать stealing — W1 будет самым долгим, разница видна на таймингах.
- Перегрузить другого воркера (W2/W3).
- Добавить "таксономию" задач: тяжёлые воркеру N и т.д.

## Real world

Java ForkJoinPool, Go runtime (work stealing в goroutines), Ray.
