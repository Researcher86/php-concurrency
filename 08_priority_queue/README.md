# 08. Priority Queue

Очередь с приоритетами — за счёт типов сообщений System V.

## Задача

Задачи с разным приоритетом: важные должны обрабатываться раньше, даже если
они пришли позже.

## Как работает

- System V очередь хранит сообщения по типам; `msg_send($q, $type, ...)` —
  тип = приоритет.
- `msg_receive($q, $type, ...)`:
  - `type = 1` — берёт сообщение с **наименьшим** номером типа (наивысший
    приоритет);
  - `type = -N` — берёт первое сообщение с типом ≤ N (другой порядок).
- Воркер всегда забирает самую приоритетную задачу.

## IPC

System V очередь (`msg_send`/`msg_receive`), тип сообщения как приоритет.

## Паттерн

**Priority Queue** поверх SysV типов сообщений.

## Запуск

```bash
docker compose exec -T php php /app/08_priority_queue/main.php
```

## Что попробовать изменить

- Добавить 4-й уровень приоритета.
- Изменить порядок отправки (важные последними) — они всё равно обработаются
  первыми.
- Поиграть с `type = -N` в `msg_receive` и посмотреть на другой порядок.

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐ — «бесплатно» поверх типов сообщений SysV.
**Failure modes**: переполнение одной приоритетной группы; starvation — низкие
приоритеты могут не получить процессора, если высокие идут непрерывно.
**Guarantees**: `msg_receive($q, $type, ...)` берёт сообщения по приоритету;
порядок FIFO сохраняется внутри одного типа; абсолютный порядок между типами
гарантирован.
