# 34. Cooperative Concurrency

Кооперативное переключение между фибрами и контраст с процессами: кто и когда
даёт/забирает управление.

## Задача

Показать, как фибры переключаются «по доброй воле» (в точках `suspend()`), и
что `sleep()`/блокирующий ввод-вывод внутри фибры блокируют весь процесс —
это фундаментальное отличие от goroutine в Go.

## Как работает

- Три фибры-задачи делают шаги и после каждого `suspend()` отдают управление
  обратно; главный цикл будит их по кругу (round-robin) до завершения.
- **Анти-паттерн**: фибра вызывает `sleep(1)` — процесс замирает целиком,
  потому что `sleep()` не является кооперативной точкой.
- **Контраст**: `pcntl_fork()` — процессы планирует ядро; порядок
  parent/child произволен (вытесняющее планирование).

## Терминология

- **Cooperative (кооперативное)** — переключение только в точках, где задача
  сама отдаёт управление (`Fiber::suspend()`).
- **Preemptive (вытесняющее)** — ОС сама решает, когда вытеснить задачу
  (процессы/потоки).
- **Concurrency ≠ Parallelism** — фибры дают concurrency (много задач в одном
  потоке), но не parallelism (одновременное исполнение).

## Блокирующий вызов vs suspend (ключ ко всему дальше)

```php
sleep(1);               // БЛОКИРУЕТ процесс: ничего другое не выполнится
Fiber::suspend();       // кооперативно: управление отдано, вернутся по resume()
```

Поэтому в уроке 36 мы свяжем фибры с `stream_select()`: фибры будут ждать
готовности сокетов через `suspend()`, а будить их будет event loop.

## IPC

Нет — в отличие от `pcntl_fork()`, фибры не требуют IPC и разделяют переменные
напрямую (это тот же процесс).

## Паттерн

**Cooperative Multitasking (round-robin)** — планирование в userland.

## Запуск

```bash
docker compose exec -T php php /app/34_cooperative_concurrency/main.php
```

## Что попробовать изменить

- Убрать `Fiber::suspend()` из фибры — она выполнится до конца и заблокирует
  всех (наглядно покажет разницу между «задача заснула» и «задача отдала
  управление»).
- Заменить `sleep()` в анти-паттерне на несколько `Fiber::suspend()` и
  посмотреть на тайминги.
- Добавить фибре приоритет (первым будить её чаще).

## Complexity / Failure modes / Guarantees

**Complexity**: ⭐⭐⭐⭐ — легко спутать непараллельное переключение с
параллелизмом; отладка межфиберных взаимодействий непривычна.
**Failure modes**: блокирующий вызов внутри фибры — вся программа встаёт;
фибры не дают скорости CPU-bound задачам; недовозобновлённая фибра — warning
при сборке мусора.
**Guarantees**: переключение детерминированное и полностью под контролем кода
(пока не вмешивается блокирующий вызов); фибры в одном процессе безопасно
делят состояние без семафоров.
