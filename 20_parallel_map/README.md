# 29. Parallel Map

`array_map()`, но элементы обрабатываются параллельно в N процессах —
с сохранением порядка.

## Задача

Есть `$items` и функция. Хочется `array_map($fn, $items)` с бонусом:
элементы считаются в N воркерах одновременно, а результат сохраняет
исходный порядок.

## Как работает

- **Map** — разбиваем вход на пары (index, value).
- **Fan-Out** — задачи с индексом уходят в общую очередь воркерам.
- **Fan-In** — результаты собираются и раскладываются по индексу
  (`$results[$parsed['index']]`), после — `ksort`.
- Итог: `[1,4,9,16,25,36]` за ≈ (число элементов ÷ воркеров) × время одной
  задачи (в демо 6×30мс / 3 воркера ≈ 60мс + оверхед).

## IPC

Две System V очереди (task/result); payload — `serialize(['index' => ..])`.

## Паттерн

**MapReduce (фаза map)** / parallel map — fan-out + fan-in с сохранением
порядка.

## Запуск

```bash
docker compose exec -T php php /app/29_parallel_map/main.php
```

## Что попробовать изменить

- Сравнить время с 1 и 4 воркерами.
- Сделать функцию тяжелее (`usleep` больше) — выигрыш от параллелизма растёт.
- Добавить reduce после map (сумма результатов).

## Real world

MapReduce/Hadoop, `parallel` ext в PHP, Go `sync.Map`, image processing
pipelines.
