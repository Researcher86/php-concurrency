# 03. Worker Pool

Пул процессов-воркеров, разбирающих общую очередь задач.
Эталон остановки по сигналу (SIGTERM + drain).

## Задача

Вместо выполнения задач в одном процессе — держать N воркеров-процессов,
каждый берёт задачу из общей очереди, обрабатывает и берёт следующую.

## Как работает

- Мастер форкает N воркеров, каждый крутит цикл `msg_receive` + обработка.
- Остановка — сигналом: мастер шлёт воркерам SIGTERM.
- Сигнальную диспозицию дети **наследуют** от родителя при fork — поэтому
  важно объявить хендлер ДО `pcntl_fork()`: иначе воркеры, форкнутые до
  установки хендлера, получат дефолтное поведение (мгновенный выход).
- Воркер по SIGTERM не выходит сразу, а **доедает очередь (drain)** и выходит
  сам — ни одна задача не теряется.

## IPC

System V очередь (`msg_get_queue`/`msg_send`/`msg_receive`), сигналы
(`pcntl_signal` + `pcntl_async_signals(true)`), `pcntl_waitpid`.

## Паттерн

**Worker Pool / Competing Consumers** — несколько потребителей борются за
задачи из одной очереди.

## Запуск

```bash
docker compose exec -T php php /app/03_worker_pool/main.php
```

## Что попробовать изменить

- Увеличить `WORKER_COUNT` и посмотреть, как быстрее разбирается очередь.
- Заменить drain на мгновенный `exit` в хендлере — часть задач потеряется.
- Переместить `pcntl_signal` ПОСЛЕ fork — ранний SIGTERM доставится воркеру
  с дефолтной диспозицией, и он умрёт мгновенно (анти-паттерн).

## Real world

PHP-FPM (`pm.start_servers`), очереди задач, фоновые обработчики.
