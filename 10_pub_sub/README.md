# 10. Pub-Sub

Издатели и подписчики: каждый подписчик получает свою копию сообщения по теме.

## Задача

Publishers шлют сообщения по темам. Subscribers подписаны на темы и получают
каждое сообщение своей темы — независимо друг от друга (один-ко-многим).

## Как работает

- Два publisher'а шлют сообщения по темам `alpha` и `beta`.
- Subscriber S1 подписан на `alpha`, S2 — на `alpha` + `beta`.
- Каждый подписчик получает **свою копию** через отдельный pipe (иначе
  сообщение забрал бы один из подписчиков — это уже был бы competing consumer).
- Отличие от очереди: сообщение НЕ потребляется одним, а копируется всем
  подписчикам.

## IPC

Unix socket pair (`stream_socket_pair`) на каждого подписчика; Системные
очереди/темы.

## Паттерн

**Publisher-Subscriber** (в отличие от queue: broadcast, не competing).

## Запуск

```bash
docker compose exec -T php php /app/10_pub_sub/main.php
```

## Что попробовать изменить

- Добавить тему `gamma` и подписку на неё.
- Подписать одного подписчика на все темы.
- Заменить pipes на очередь System V — и увидеть, что копирование пропадает.

## Real world

RabbitMQ exchanges (fanout/topic), Redis Pub/Sub, WebSocket-рассылки.
