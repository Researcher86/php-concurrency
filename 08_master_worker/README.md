# 08. Master-Worker

Классическая схема «мастер раздаёт, воркеры работают, результаты возвращаются».

## Задача

Мастер координирует воркеров: раздаёт задачи, получает результаты, управляет
жизненным циклом. Воркеры сами ничего не решают.

## Как работает

- Мастер форкает воркеров.
- Три очереди:
  - `taskQueue` — задачи от мастера воркерам;
  - `resultQueue` — результаты от воркеров мастеру;
  - `ctrlQueue` — управляющие сообщения (например, остановка).

## IPC

Три System V очереди (`msg_get_queue` + `ftok` с разными id); `pcntl_fork()`
с проверкой на -1; `pcntl_waitpid`.

## Паттерн

**Master-Worker** — центральный координатор + пул исполнителей.

## Запуск

```bash
docker compose exec -T php php /app/08_master_worker/main.php
```

## Что попробовать изменить

- Добавить третью очередь под контроль (пауза/резюме воркеров).
- Сделать мастер-персистентным: не завершаться, а ждать новых задач.
- Передавать в taskQueue payload, а не только id задачи.

## Real world

Web-серверы (master + worker pool), Celery, gunicorn.
